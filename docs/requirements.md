# AgentFailures 要件定義

最終更新: 2026-09-08

## 1. 目的

自身が運用する AI エージェント群が「失敗談」を蓄積・参照するためのナレッジストア、
および当該ストアを読み書きするリモート MCP サーバーを構築する。

エージェントはタスク実行前に該当する失敗談を参照し、実行計画へ反映することを想定する。
本フェーズの目的は最小構成を稼働させ、実データを蓄積したうえで要件を検証することにある。

## 2. 設計方針

- 書き込みはエージェントのみが行い、閲覧は人間も行う。したがって保存形式は人間可読であること。
- 成功事例ではなく失敗事例を蓄積対象とする。
- PC・スマートフォン双方のクライアントから参照するため、ローカル常駐型ではなくホスト型とする。

## 3. 技術スタック

本項は確定事項であり、代替案の検討は行わない。

| 区分 | 採用技術 |
| --- | --- |
| ストア | Supabase (PostgreSQL) |
| MCP サーバー | TypeScript / Cloudflare Workers / Streamable HTTP |
| SDK | `@modelcontextprotocol/sdk` |
| デプロイ | wrangler |

## 4. データスキーマ

以下を必須項目とする。

| 項目 | 型 | 説明 |
| --- | --- | --- |
| `id` | uuid | 主キー |
| `created_at` | timestamptz | 登録日時 |
| `domain` | text | 対象領域（例: `app-dev`, `notion-integration`, `scheduling`） |
| `environment` | text | 実行環境およびバージョン情報 |
| `attempted` | text | 何をしようとしたか |
| `observed` | text | 実際に何が起きたか。観測された事実のみを記載する |
| `cause` | text | 原因 |
| `cause_is_assumption` | boolean | 原因が推定である場合は `true` |
| `workaround` | text | 回避策（任意） |
| `tags` | text[] | タグ |

## 5. MCP ツール仕様

実装対象は以下の 2 ツールに限定する。

### 5.1 `search_failures`

- 入力
  - `domain`（任意）
  - `environment`（任意）
  - `query`（任意・全文検索）
  - `limit`（既定 3・最大 5）
- 出力
  - 該当する失敗談を新しい順に返却する。
  - 上限件数を超えて返却しないこと。

### 5.2 `record_failure`

- 入力: 第 4 章の必須項目。
- 必須項目が欠落している場合はエラーを返し、登録を行わないこと。
- ツール説明文に「原因が推定である場合は `cause_is_assumption` を `true` にすること」を明記すること。

## 6. 認証

環境変数に格納した固定トークンを HTTP ヘッダで照合する方式とする。OAuth は実装しない。

## 7. スコープ外

以下は将来的な拡張候補であり、本フェーズでは実装しない。先回りした実装も行わない。

- Notion 連携・同期
- ベクトル検索 / pgvector
- カテゴリの自動分類、審査エージェント、削除機構
- 管理用 UI

## 8. 進め方

1. ディレクトリ構成と実装方針を提示し、着手前に確認を取る。
2. Supabase のマイグレーションを作成する。
3. MCP サーバーを実装する。
4. ローカルでの動作確認手順、およびデプロイ手順を提示する。
5. 疎通確認用の curl コマンド、および MCP クライアントの設定例を提示する。

## 9. 運用上の制約

- `.env.example` を用意し、シークレットはコミットしない。
- セットアップ手順は README に記載する。
