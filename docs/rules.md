# 規則

失敗談ストアに溜まった記録から蒸留した、**各エージェントの CLAUDE.md へ配るための規則**。

本書は失敗談ストアとは役割が違う。

| | 失敗談ストア（`failures` テーブル） | 本書 |
| --- | --- | --- |
| 役割 | **証拠**。何が起きたかの一次記録 | **知識**。同じ型の失敗を 1 本へ統合したもの |
| 書き方 | 追記のみ。既存の記録は書き換えない | **編集・統合する** |
| 読まれ方 | 検索しないと出てこない | **CLAUDE.md へ配られ、無条件に読まれる** |

115 件の記録のうち、上位 2 つの型（静かに失敗する／検証が甘い）だけで半分を占めていた。
件数ではなく型で畳むのが本書の目的である。

## 書き込みの規約

規則は、以後すべてのエージェントの振る舞いを縛る。**蓄積による指示の注入を防ぐため、
書き込める内容を次のとおり限定する。**

- **編集案はどのエージェントが出してもよい。** 既存の規則の改稿も、新規追加も、廃止の提案もできる
- **公開は人が承認する。** 本書への変更は pull request として出し、**マージをもって承認とする**
- **エージェントは自分の提案を自分でマージしない。** `review-decisions.csv` と同じ規律である
  （開発側が自分への指摘を無効化できる構造を作らない）
- 由来となった失敗談の id を必ず書く。**根拠の無い規則を置かない**

## 配布の仕組み

各リポジトリの `CLAUDE.md` にある管理ブロックへ、`scripts/sync-rules.mjs` が本書から
規則を差し込む。ブロックの外は触らない。

```markdown
<!-- agentfailures:rules:start synced=YYYY-MM-DD source=<sha> -->
<!-- agentfailures:rules:end -->
```

**`synced=` を配布物そのものに刻むのは意図的である。** 同期が止まったことが、
CLAUDE.md を読むすべてのエージェントに毎回見える。別の監視を用意しなくてよい。
keep-alive が 2 週間止まっていたことに気づけなかったのは、動いた証拠が成果物に
残らなかったためである（失敗談 `5a236586`）。

## 書式

**見出しの直後の段落が、そのまま各 CLAUDE.md へ配られる本文である。**
1〜2 文に収め、重複して書かない（同じ文を二箇所に置くと必ず片方が古くなる）。
以降の箇条書きは本書にのみ残り、配布されない。

## pkill-self-kill

**`pkill -f` を使わない。** パターン文字列は、そのコマンドを実行しているシェル自身のコマンドラインにも一致するため、自分のシェルが落ちる（exit code 144）。プロセスはポート（`fuser -k`）か PID で止め、停止と後続の作業を同じ呼び出しに入れない。

- 種別: 事実
- 由来: 6 件 — `b9933ac2` `51a00a9e` `b4f01628` `14d67d7c` `0f6215ba` `a8d2f7fe`
- 備考: 「別の呼び出しに分ければよい」は回避策として不十分だった（`14d67d7c`）。
  `0f6215ba` は「過去に記録済みだったが事前の検索を怠り再発した」と自己申告している

## verify-by-breaking

**「通った」は確かめたことにならない。** テストや検査は、**わざと壊して落ちることを確認**してから信頼する。壊した値が期待値と偶然一致していないか、測っている対象が本当にその事象を捉えているかも併せて見る。

- 種別: 行動
- 由来: 23 件（`false-pass` / `break-test` / `premature-completion` 系）
- 備考: **本書に置いても効果は期待しにくい。** 既に `lessons.md` とレビュー観点に
  書いてあるのに 23 件起きている。行動の型は、行為の瞬間に差し戻す仕組み
  （Stop フックの自動レビュー）の方が実績がある

## silent-failure-first

**失敗は静かに起きると考える。** 文字列置換の不一致、`echo ok` に埋もれた失敗、キャッシュ越しの古い結果はいずれも例外を出さない。**件数・差分・タイムスタンプで確認する**こと。「エラーが出ていない」は成功の証拠にならない。

- 種別: 行動
- 由来: 34 件（`silent-failure` タグ）
- 備考: 最大のクラスタ。個別の技術ではなく判断の型である

## no-newline-chained-commands

**複数のコマンドを改行で並べない。** 前段が失敗しても後続は実行され、末尾の成功出力に埋もれる。`&&` でつなぐか `set -e` を置く。

- 種別: 事実
- 由来: 1 件 — `0c40b4a8`
- 備考: 件数は少ないが、`silent-failure` の 34 件のうち複数がこの形で表面化している

## suspect-the-cache

**直らない・再現しないときは、まずキャッシュを疑う。** `.next/cache` はビルドとプロセス再起動を跨いで残り、`unstable_cache` は値を JSON 化して保存する。テーブルを消しても本番と同じエラーが再現しないことがある。

- 種別: 事実
- 由来: 8 件 — `539a0b39` `a026c5d5` `c1bb4382` `ad19ef3d` `acf97379` `13eb8b94` `52c45400` ほか

## no-recall-for-specs

**仕様・バージョン・料金・上限を記憶で断定しない。** 一次情報を引くか、「確認できなかった」と書く。**読む層を間違えた一次情報は、推測より質が悪い**（断定の強さだけが上がり、誤りが検証されにくくなる）。

- 種別: 行動
- 由来: 7 件 — `7617838f` `cae8534f` `11497dcb` `048171f9` `891c5ec4` `7b845387` ほか
- 備考: Cloudflare の cron パーサで、内部表現を入力の番号付けと取り違えて誤った
  結論を断定した例がある（`5d9ac898`）

## search-before-planning

**着手前に AgentFailures の `search_failures` を引く。** 同じ失敗が記録済みであることに気づかず再発した例が 6 件ある。

- 種別: 行動
- 由来: 6 件（`recurrence` / `repeated-failure` / `ignored-known-failure` タグ）
- 備考: **この規則自体が、本書を作る原因になった失敗である。** 測定では
  5 日間で検索 0 件・書き込み 10 件であり、自発的な検索は当てにならなかった

## windows-powershell

**Windows PowerShell 5.1 では `curl` が `Invoke-WebRequest` の別名である。** 引数体系が違うため `curl.exe` を使う。`.ps1` は BOM 付き UTF-8 で保存し（BOM 無しは CP932 として読まれる）、`-Body` に日本語を渡すときは `[System.Text.Encoding]::UTF8.GetBytes()` でバイト列にする。

- 種別: 事実
- 由来: 2 件 — `29361c65` `098e3bf6`

## cloud-container-constraints

**クラウドのコンテナには固有の制約がある。** ロケールが POSIX のため `navigator.language` が不正値になり `Intl` が例外を出す。Chromium の実行ファイルはバージョン番号付きディレクトリの下にある。外部ホストは許可制で、**設定変更は実行中のセッションに反映されない**。起動したプロセスはコンテナの作り直しで落ちる。

- 種別: 事実
- 由来: 8 件 — `65bfff39` `fc7487e1` `42e365c6` `66c5c8fa` `6bba9c94` `e71be4ab` `fc055558` ほか

## unicode-escape-expanded

**ツール引数の `\uXXXX` は、シェルに渡る前に実際の文字へ展開される。** 引用符付きヒアドキュメントでも防げない。エスケープ列をそのまま書き込みたい場合は、別の経路（ファイル経由など）を使う。

- 種別: 事実
- 由来: 2 件 — `f018d3bf` `0cf9eba5`

## git-pitfalls

**git の挙動で 3 点。** `git rm` はインデックスに削除を登録するため、`git add` で指定していないファイルも次の commit に入る。squash マージ後の旧ブランチは master と共通の祖先を持たず、追記同士が衝突する。**開いている pull request があるうちは作業ブランチを作り直さない。**

- 種別: 事実
- 由来: 4 件 — `5e158afe` `d0a6d253` `ccd72fdf` `0796728c`
