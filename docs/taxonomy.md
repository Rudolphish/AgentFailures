# domain と tags の使い分け

`domain` は完全一致で検索するため、表記が揺れると絞り込みが機能しなくなる。
実際、運用開始から数時間で記録 9 件に対し `domain` が 8 種類まで分散し、
`domain` による絞り込みが成立しない状態になった。本書はその対応として定めた規約である。

規約の正本は [`src/schema.ts`](../src/schema.ts) の各項目の説明文にある。
記録するエージェントはツールの説明文を通じてこれを読むため、
本書と実装が食い違った場合は実装が優先される。

**`domain` の値の一覧は、どこにも正本を置いていない。** 実データが正本である
（`select distinct domain from failures`）。手で書いた一覧を正本とする運用は
2026-11-19 にやめた。理由は下記「domain の語彙」に書く。

## 使い分け

| 項目 | 表すもの | 例 |
| --- | --- | --- |
| `domain` | 失敗が起きた場所の**技術** | `nextjs` / `cloudflare-workers` |
| `tags` | 失敗の**性質・話題・関連技術** | `silent-failure` / `caching` / `prisma` |

判断の基準は「**その技術に触るときに引きたいか**」である。
Next.js のアプリを触るなら `domain: nextjs` で関連する失敗を一望できる、という単位にする。

`notification-design` や `api-cache-design` のような話題の名称を `domain` に入れると、
記録ごとに新しい値が生まれて一望できなくなる。話題は `tags` へ入れる。

## domain の語彙

**固定の一覧は持たない。** 2026-11-19 まで `src/schema.ts` の `KNOWN_DOMAINS` に
7 個を列挙し、「ここが正本であり、追加にはデプロイを要する」としていた。
**この運用は実態と合っていなかった。**

- 実データには **32 種類**あった（136 件時点）。説明文が許容していた「該当が無ければ
  新しく作る」の経路から増え続け、列挙は追随していなかった
- 列挙に無い値は**絞り込みの対象として見えない**。`playwright` の 7 件は、
  列挙だけを見ているエージェントには到達できなかった
- `domain` は**完全一致**であるため、存在しない値を渡すと記録があっても 0 件になる。
  古い一覧は「0 件＝記録が無い」という誤読を生む

現在の方針は次のとおり。

- ツールの説明文には**件数上位の数個だけを例として載せる**（`src/schema.ts` の
  `COMMON_DOMAINS`）。全件を書き並べない
- 検索では、**値が不確かなら `domain` を省いて `query` だけで引く**
- 記録では、**先に `search_failures` で同種の記録を引き、その `domain` に合わせる**。
  既存の値の再利用を、一覧の暗記ではなく検索で担保する

件数上位（2026-11-19 / 136 件）: `claude-code` 43 / `nextjs` 25 /
`github-actions` 10 / `playwright` 7 / `prisma` 6 / `discord-api` 5 / `supabase` 5。
**この表も時点の記録であり、正本ではない。** 最新は実データを数えること。

## tags の付け方

次の 3 種類を意識して付ける。

1. **失敗の性質**（最低 1 つ）
   `silent-failure` / `security` / `data-loss` / `encoding` / `quota` /
   `race-condition` / `permissions` など
2. **話題・設計パターン**
   `caching` / `idempotency` / `authorization` / `notification` / `planning` など
3. **`domain` 以外の関連技術**
   `prisma` / `pnpm` / `discord` / `cron` など

1 を必ず含めるのは、**技術が変わっても失敗の性質は繰り返される**ためである。
`silent-failure` で横断的に引けることには、`domain` による絞り込みとは別の価値がある。

## 語彙が増えすぎたときは

`domain` が増え続ける場合、それは技術が増えたのではなく、規約が守られていない可能性が高い。
ただし**一覧を書き足して追随しようとしないこと。** それは 2026-11-19 までやって
失敗した方法である。見るべきは「記録の前に `search_failures` を引いているか」で、
引いていれば既存の値に寄る。引かずに書くと新語が増える。
